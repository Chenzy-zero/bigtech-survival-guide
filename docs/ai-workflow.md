# AI 辅助开发工作流

本项目可以使用 Codex、Claude Code、GitHub Copilot 或 Cursor 协作。根目录 AGENTS.md 是通用规则的唯一事实来源，各工具专属文件只做入口说明，避免规则分叉。

## 推荐流程

### 1. 先规划

适用于新增页面、调整事件模型、扩展剧情引擎等中型任务。

建议提示词：

~~~text
先阅读 AGENTS.md 和相关 docs。请检查当前实现，不要立即修改文件。
请说明你理解的目标、涉及文件、最小实现方案、风险和验证方法。
优先复用现有结构，不要引入非必要依赖。
~~~

### 2. 小步实现

~~~text
按已确认的计划实现最小变更。保持剧情数据与 UI/引擎分离。
不要顺带重构无关代码。完成后运行适用的测试和构建，并检查 diff。
~~~

### 3. 自我审查

~~~text
请像代码审查者一样检查本次 diff：寻找错误的剧情跳转、无法到达的结局、重开后残留状态、手机端可用性问题和无必要的复杂度。
请先报告问题，再修复确实存在的问题，最后重新运行验证。
~~~

### 4. 编写或修改剧情

~~~text
请为指定章节设计职场事件。每个事件包含唯一 ID、背景、2–4 个选项、结果反馈和有效跳转。
陷阱必须有可推断的线索；不同选项应有真实后果。
如使用真实资料，请引用 docs/research/sources.md 中的来源 ID，并区分事实与虚构改编。
不要把未经证实的传闻写成具体公司的事实。
~~~

## 给 AI 的任务上下文

每次任务尽量明确：
- 要改变的用户体验。
- 不在本次范围内的内容。
- 可修改的文件或模块。
- 必须保留的行为。
- 验收标准。
- 需要运行的验证。

## 防止 AI 过度开发

- 不因“未来可能需要”就提前增加后端、数据库、插件系统或通用框架。
- 不把简单的选择题扩展成大型 RPG。
- 不生成没有来源标注的“真实案例”。
- 不在未运行测试时声称测试通过。
- 任何新增依赖都应说明为何现有原生能力不足。
