# 开发路线图

## 阶段 0：项目基础（当前）

- [x] 建立项目说明和文档导航。
- [x] 建立 AI 辅助开发约定。
- [x] 归档已收集的公开案例、媒体资料和玩法参考。
- [x] 确定手机优先、单页面、选择驱动的 MVP 方向。
- [ ] 审阅并确认技术方案。

## 阶段 1：最小可玩原型

- 初始化 Vite + TypeScript 的轻量前端项目。
- 完成首页、事件页和结局页。
- 实现单事件展示、选项选择、事件跳转和重新开始。
- 编写 8–12 个事件，至少包含一个存活路径和多个失败路径。
- 添加事件数据校验。
- 在手机视口中验证触控和阅读体验。

完成标准：玩家可以从首页开始，连续做选择，触发结局，再重新开始。

## 阶段 2：内容 MVP

- 扩充到约 12–20 个事件。
- 覆盖求职、入职、试用期、需求变更和首次紧急任务。
- 增加选择历史与结局回顾。
- 为基于真实素材的事件登记来源。
- 运行跳转、可达性和重开状态测试。

完成标准：存在一条完整、可理解的存活路径，失败有原因，剧情分支有实际意义。

## 阶段 3：公开试用

- 修复移动端体验问题。
- 增加基础页面元信息、图标和分享预览。
- 配置构建检查和静态部署。
- 请少量玩家试玩，记录难以理解的选项和不公平陷阱。

完成标准：公开链接可以在手机浏览器直接游玩，无需登录或安装。

## 阶段 4：按反馈扩展（可选）

- 增加团建、同事关系、绩效、组织调整等事件。
- 视需要引入少量精力/信任等状态。
- 增加隐藏结局、难度模式或本地存档。
- 考虑是否需要剧情编辑工具。

## 当前不做

账号体系、服务端、多人模式、复杂数值养成和运行时 AI 剧情生成都不属于 MVP。
