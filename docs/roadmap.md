# 开发路线图

本文件描述阶段目标，不是任务跟踪系统。**所有实际需求、任务和 Bug 都通过 GitHub Issues 管理**，每个 Issue 指向真实的仓库文档或代码路径，并包含验收标准。请从 [GitHub Issues](https://github.com/Chenzy-zero/bigtech-survival-guide/issues) 查看进展。

## 阶段 0：项目基础

目标：建立产品定义、AI 开发约定、研究资料归档和 Issue-first 工作流。

完成标准：
- 产品基调明确为荒诞职场讽刺，而非严肃指南。
- 产品需求、游戏设计、技术方案和研究来源有独立文档。
- Issue、文档、代码与 PR 的关系清楚可执行。

## 阶段 1：最小可玩原型

目标：实现从开始到结局的完整手机网页体验。

预期工作范围：
- 初始化轻量 Vite + TypeScript 项目。
- 完成首页、事件页、反馈和结局页。
- 实现选项选择、事件跳转、陷阱触发与重新开始。
- 编写 8–12 个事件，至少包含一个存活路径和多个失败路径。
- 添加事件数据校验。
- 在手机视口中验证触控和阅读体验。

完成标准：玩家可以从首页开始，连续做选择，触发结局，再重新开始。

## 阶段 2：内容 MVP

目标：让游戏具有完整的第一轮可玩体验。

预期工作范围：
- 扩充到约 12–20 个事件。
- 覆盖求职、入职、试用期、黑话、同事关系和首次紧急任务。
- 加入若干“看似正确、随后反噬”的反转和“摸鱼/拍马屁暂时奏效”的荒诞路径。
- 增加选择历史与结局回顾。
- 为基于真实素材的事件登记来源。
- 运行跳转、可达性和重开状态测试。

完成标准：至少有一条完整存活路径，失败有原因，剧情分支有意义，反转有线索。

## 阶段 3：公开试用

目标：让玩家可以通过公开链接直接游玩。

预期工作范围：
- 修复移动端体验问题。
- 增加基础页面元信息、图标和分享预览。
- 配置构建检查和静态部署。
- 收集试玩反馈并通过 Issues 跟踪。

完成标准：无需登录或安装即可在手机浏览器游玩。

## 阶段 4：按反馈扩展（可选）

根据 Issues 和真实试玩反馈，考虑增加团建、绩效、组织调整、隐藏结局、本地存档或少量状态数值。不要在验证核心玩法之前增加复杂系统。

## 当前不做

账号体系、服务端、多人模式、复杂数值养成和运行时 AI 剧情生成都不属于 MVP。
