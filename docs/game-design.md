# 游戏设计与核心规则

## 1. 核心概念：反向生存指南

这不是答题闯关，也不是“学会正确职场技巧就能成功”的模拟器。玩家扮演新人，以为自己只要专业、负责、坦诚、勤奋，就能得到公平评价；但这家虚构大厂的口头价值观与实际奖励机制经常相反。

游戏的主要笑点来自：你按常理解决了眼前问题，却因此触发了下一层荒诞规则。相反，拍马屁、装忙、甩锅、抢功或摸鱼可能意外地活得更久。玩家的目标是生存，不是拿到“最佳员工”奖章。

## 2. 章节建议

1. **求职幻觉**：投简历、笔试、面试、谈薪资、签 Offer。
2. **新人驯化**：入职、花名、内部黑话、认识同事、第一次周会。
3. **试用期迷宫**：模糊需求、汇报、绩效沟通、需求变更。
4. **紧急任务地狱**：临时上线、测试不足、线上故障、责任复盘。
5. **组织生存学**：团建、同事关系、跨部门协作、绩效、晋升与组织调整。

MVP 先做 12–20 个事件，覆盖求职到试用期和第一次紧急任务，不必一次写完所有章节。

## 3. 单个事件的结构

每个事件包含：
- 唯一 ID、章节、标题、情境描述。
- 2–4 个行动选项。
- 选项反馈与目标事件，或明确的成功/失败结局。
- 可选剧情标记、反转线索和来源引用。
- 结局应说明玩家为什么活下来或为什么被坑。

选项不必公平，但应当有意义。看似正确的选择可以成为后续陷阱；看似不正经的选择可以让玩家短期脱险，却可能埋下另一种麻烦。不同选择不能只是换个措辞后通往完全相同的结果。

## 4. 反转与陷阱设计规则

推荐采用“表面规则—隐藏激励—反转结果”的结构：

1. **表面规则**：主管说“我们重视结果和质量”。
2. **隐藏激励**：主管真正害怕的是周报里没有可展示的进展。
3. **玩家选择**：认真花时间修复根因，或先做一个可展示的进度截图。
4. **反转结果**：认真修复导致进度汇报看起来停滞，玩家被追问；截图策略暂时过关，但后续可能因为实际问题未解决而爆雷。

其他可用的荒诞逻辑：
- 把工作做好，大家默认你还能多做一点。
- 主动承认风险，被认为缺乏解决问题的能力；把风险包装成“已对齐”，反而更受认可。
- 帮同事解决问题，自己的交付延期；拒绝帮忙却会在绩效里被称为“聚焦核心目标”。
- 真正休息的人被质疑不够投入；在群里高频发言的人被误认为很忙。
- 拍马屁可能让你过关，但拍错对象也会立即翻车。
- 摸鱼可能是自我保护，也可能让你错过关键情报。

公平性要求：
- 反转应有线索，可以来自措辞、人物动机、之前的选择或同事的提示。
- 可以让玩家第一次误判，但失败后要能理解自己为什么被坑。
- 不要每题都让“认真做事”立即失败，也不要让拍马屁/摸鱼成为固定答案；荒诞来自具体情境。
- 允许一些结局是纯粹荒谬的，但不能让整个游戏变成无因果的随机惩罚。

## 5. 选择结果与状态

第一版只需要：
- currentEventId：当前事件。
- decisions：本局选择历史。
- flags：剧情标记，例如 manager_wants_visible_progress、coworker_shared_rumor、pretended_to_be_busy。
- status：playing、won 或 lost。

暂不加入复杂属性面板。通过剧情标记和事件跳转体现玩家的选择。后续如果玩法确实需要，再考虑精力、主管信任或职场声望等数值。

## 6. 结局建议

MVP 至少包含：
- **苟到转正**：玩家终于学会了组织真正奖励什么，但并不意味着获得幸福。
- **背锅侠**：把工作做好，却没留下任何人愿意承认的责任记录。
- **优秀员工奖**：被评为“特别能扛事”，奖励是更多工作。
- **摸鱼大师**：善于控制预期、隐藏忙闲，意外存活。
- **拍马屁翻车**：误判了真正有权力的人。
- **主动离职**：玩家决定不再参加这场游戏。
- **过劳中断**：作为严肃的警示性结局，而不是纯搞笑彩蛋。

后续可以增加“成为自己曾经讨厌的主管”“靠 PPT 晋升”“全组裁员但你负责做裁员汇报”等隐藏结局。

## 7. 内容语气

主调是荒诞、黑色幽默、冷面叙述和反职场鸡汤。不要写成一本严肃的职场技巧手册。人物可以有复杂动机，但组织激励机制应持续制造价值观错位。真实案例只能作为灵感，使用虚构公司与复合剧情，不把未经证实的传闻写成事实。
