# 游戏设计与核心规则

## 1. 核心概念

玩家不是在回答知识考试，而是在信息不完整、时间有限、上下级关系不对等的职场情境里做选择。某些选项会立即触发陷阱，某些选项会改变后续事件。游戏的目标是“尽可能活下去”，而不是让玩家猜作者唯一认可的答案。

## 2. 建议的章节顺序

1. 求职：投简历、笔试、面试、谈薪资、签 Offer。
2. 新人入职：入职流程、花名/内部称呼、认识同事、第一次周会。
3. 试用期：任务拆解、汇报、需求变更、绩效沟通。
4. 项目救火：紧急上线、测试不足、线上故障、责任复盘。
5. 组织生存：团建、职场黑话、跨部门协作、绩效和组织调整。

MVP 不需要一次覆盖所有主题。建议先完成前三章和一个紧急任务事件链，之后再扩展。

## 3. 单个事件的结构

每个事件应包含：
- 唯一 ID。
- 章节、标题和情境描述。
- 2–4 个选项。
- 每个选项的后果：进入下一事件，或进入明确的失败/成功结局。
- 可选的反馈文字，解释短期结果。
- 可选的来源引用与内容标签。

避免让选项只是在措辞上不同、结果却完全一样。即使多个选择最终通往同一事件，也应在反馈、人物态度或后续标记上有所区别。

## 4. 陷阱与失败

失败应来自玩家忽视了情境中可推断的风险，而不是随机惩罚。例如：
- 没有确认需求范围和验收标准，就承诺不可能的截止时间。
- 明知上线存在重大风险，却为了讨好上级跳过必要检查。
- 在敏感的绩效沟通中做出冲动承诺，或在缺乏信息时贸然指责他人。
- 持续忽略疲劳和身体警告，导致无法继续工作。

公平性规则：
- 陷阱要能从事件文本或此前线索中推断，避免毫无提示的“作者杀”。
- 失败页说明本次触发了什么风险，并提供重开按钮。
- 不要将“拒绝违法或明显不合理的要求”机械设置成必然失败。
- 失败结局可以幽默，但不把严重健康后果轻佻化。

## 5. 轻量状态设计

第一版建议先使用“剧情标记 + 选择历史 + 进度”，不急于加入大量数值：
- 选择历史：记录本局做过的选择，用于结局回顾。
- 剧情标记：例如已经确认验收标准、获得同事帮助、留下任务记录。
- 进度：当前章节/事件序号。
- 结局：成功存活、试用期未通过、项目背锅、主动离职等。

当事件链证明确实需要长期资源取舍时，再加入少量状态，例如精力或主管信任。不要一开始就设计十几个属性。

## 6. 可重玩设计

- 部分选项改变后续事件，而不只是改变一句反馈。
- 通过隐藏标记解锁不同路径。
- 结局后显示关键选择回顾。
- 后续版本可以加入“生存天数”或“难度模式”，但不作为 MVP 的前置条件。

## 7. 内容语气

主调是现实感、冷幽默和职场荒诞。人物不必全是坏人：主管可能承受上级压力，同事可能既是竞争者也是帮助者，HR 也可能提供有用信息。复杂的人际动机比单纯的好人/坏人更有趣。

## 8. 结局建议

MVP 至少包括：
- 存活通关：通过试用期并建立可持续的工作方式。
- 试用期失败：工作交付或沟通出现问题。
- 项目背锅：关键风险未确认或证据链缺失。
- 主动离职：识别环境不匹配，选择离开。
- 过劳中断：作为严肃警示性结局，而非纯搞笑彩蛋。

后续可增加晋升、跳槽成功、成为自己曾经讨厌的主管等隐藏结局。
