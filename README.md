# 大厂生存指南 · BigTech Survival Guide

**名字叫《大厂生存指南》，但它并不打算教你如何正常地在大厂生存。**

这是一款手机优先的单页面荒诞职场选择游戏。玩家扮演刚毕业、进入一家虚构科技大厂的新人，从投简历、面试和谈薪资开始，一路经历入职、花名、职场黑话、团建、绩效、紧急任务、同事关系和组织调整。

游戏世界的潜规则荒诞而反常识：你以为专业、负责、讲道理的选择能解决问题，下一步却可能因此背锅；溜须拍马、装忙、战略性摸鱼和把工作做得“刚好够用”，反而可能让你活得更久。玩家的目标不是成为模范员工，而是在这套扭曲的组织逻辑里尽可能生存下去。

> 当前阶段：项目基础和设计文档已初始化，正在准备最小可玩原型。

## 核心体验

- 手机竖屏优先，打开页面即可开始。
- 每次只展示一个职场事件和 2–4 个选择。
- 选择会推进剧情、埋下后续陷阱、触发反转或直接结束游戏。
- “看起来正确”的选择可能成为下一步的坑；荒诞的应对方式可能意外奏效。
- 失败后揭示这次踩中了什么组织潜规则，并允许重新挑战。
- 结局可以是转正、晋升、被裁、背锅、主动离职，或成为自己曾经讨厌的那种人。

## 设计原则

1. **反职场鸡汤**：本作是黑色幽默与荒诞讽刺，不是严肃的职场教学指南。
2. **反常识但有线索**：选择结果可以反转，但要能从对话、人物动机或之前事件中找到线索，避免纯随机的作者杀。
3. **生存优先于道德积分**：游戏世界可能奖励拍马屁、装忙、甩锅和摸鱼；不把认真工作设计成稳定通关捷径。
4. **简单优先**：第一版不做账号、后端、多人玩法、复杂地图或运行时 AI 剧情生成。
5. **来源可追溯**：真实案例用于研究和启发；游戏使用虚构公司与复合剧情，不把未经证实的传闻当事实。
6. **严肃对待现实伤害**：过劳等严重健康后果可以成为剧情警示，但不作为轻佻笑料。

## 项目管理

**所有需求、开发任务和 Bug 都必须通过 GitHub Issue 管理。** Issue 必须指向仓库内真实存在的文档或代码路径，并包含可验证的验收标准；PR 必须关联 Issue。请从 [GitHub Issues](https://github.com/Chenzy-zero/bigtech-survival-guide/issues) 查看当前任务，不要把 README 或路线图当作另一套任务跟踪系统。

## 当前技术策略

第一版优先采用轻量静态网页方案：Vite + 原生 TypeScript + CSS，剧情与引擎分离。除非 MVP 证明有必要，否则不引入后端、数据库、状态管理框架或大型 UI 组件库。

## 资料与免责声明

本项目是虚构的职场荒诞讽刺游戏，不构成法律、医疗或劳动争议个案的专业意见。真实案例用于研究和启发，剧情会进行虚构化或复合改编。
